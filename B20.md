# $PYRA is a B20 — creation config + deploy-time ceremony

Decision (founder, 2026-07-16): the token ships as a **B20** — Base's native
precompile ERC-20 superset (Beryl upgrade) — not as our own ERC-20 contract.
There is deliberately no token contract in `src/`; unit tests use
[`test/mocks/MockPYRA.sol`](test/mocks/MockPYRA.sol) (same surface: ERC-20 +
EIP-2612, 9 decimals, fixed 10B), the same way one mocks USDC. Spec:
https://docs.base.org/base-chain/specs/upgrades/beryl/b20

## Creation parameters (ASSET variant)

| Param | Value |
|---|---|
| Factory precompile | `0xB20f000000000000000000000000000000000000` → `createB20(variant, salt, params, initCalls)` |
| Variant | `ASSET` |
| Name / symbol | `"Lampyra"` / `"PYRA"` |
| Decimals | **9** (1 PYRA = 1e9 base units — matches the off-chain ledger's unit math) |
| Initial admin | deployer EOA, for the genesis ceremony only |
| Supply | mint `10_000_000_000 * 1e9` (1e19) to the **PyraTreasury proxy**, once |
| Supply cap | `10_000_000_000e9` via `encodeUpdateSupplyCap` (belt-and-braces; moot after renounce) |
| Salt | caller-chosen bytes32 → deterministic token address; pick at P4 after a Sepolia dry run |

## Genesis ceremony (order matters)

1. Verify activation: registry `0x8453000000000000000000000000000000000001`
   → `isActivated("base.b20_asset")` on the target network.
2. Deploy `PyraAdmin` + the four UUPS proxies (treasury first — the mint target).
3. `createB20(ASSET, salt, encodeAssetCreateParams("Lampyra","PYRA", deployer, 9), initCalls)`
   with initCalls: `grantRole(MINT_ROLE, deployer)`, `updateSupplyCap(1e19)`.
4. `mintWithMemo(treasuryProxy, 1e19, "lampyra-genesis")` — full supply, one mint.
5. Renounce `MINT_ROLE`, then **`renounceLastAdmin()`** → every role-gated
   operation (mint, burn, pause, policy updates) becomes permanently
   uncallable. NEVER grant PAUSE/UNPAUSE/BURN/policy roles before renouncing —
   roles granted to other addresses survive renunciation.
6. Result: fixed 10B supply, transfer policies stuck at `ALWAYS_ALLOW`
   (default), unpausable, ungoverned. Strictly stronger than our "immutable
   contract" plan — there is no bytecode to even have upgrade authority over.
7. `PyraTreasury.initializeDistribution(...)` (requires the proxy to actually
   hold the full supply) → pool accounting live.
8. **`EscrowPool.setPayoutCap(...)` — set a real cap at genesis.** It defaults
   to 0 = DISABLED, and it is the only blast-radius limiter if the
   orchestrator hot key is ever compromised (`settleBatch` pays arbitrary
   recipients from the aggregate pool by design — audit finding M1,
   `audit/review-2026-07-16.md`).

## Verify on Base Sepolia BEFORE mainnet (the three unknowns)

> **Sepolia genesis executed 2026-07-16 — addresses in `deployments/84532.env`.**
> Check 1 is RESOLVED: a B20 carries a **1-byte `0xef` marker** at its address
> (EIP-3541-reserved, can never be valid EVM code), so `extcodesize == 1` and
> OZ SafeERC20 works unmodified — proven E2E (presale initializer's 2.5B
> `transferFrom` pull + escrow deposit/settle/fee, all exact to the base unit;
> cycle-replay rejected). Two operational gotchas discovered:
> **(a)** the token address derives from the CREATOR — predict with
> `cast call --from <deployer>`, and prefer parsing `B20Created` from the
> receipt; **(b)** vanilla forge cannot even *simulate* calls to the token
> (the `0xef` byte is an invalid opcode locally) — `Deploy.s.sol`'s b20 mode
> needs a `vm.etch(token, MockPYRA-runtime)` shim before the mainnet run, or
> drive the ceremony with `forge create` + `cast` as done on Sepolia.

1. **SafeERC20 / codeless-address probe** — ✅ RESOLVED (see above). The
   fallback hand-written ERC-20 is no longer needed.
2. **DEX support** — create a PYRA/WETH test pool (Aerodrome or Uniswap v3)
   on Sepolia; swap both directions.
3. **Permit is ECDSA-only** (EIP-712 domain `("Lampyra","1",chainId,token)`) —
   Coinbase Smart Wallet (contract sigs) cannot use permit; frontend must fall
   back to `approve` (smart wallets batch approve+action atomically, so no UX
   loss). Confirm the frontend path.

Tooling note: unit tests stay on vanilla forge (MockPYRA). Only the deploy
script's *local simulation* of the factory needs `base-forge`/`base-anvil`
(`base = true` in foundry.toml); on live networks the factory is just a
transaction — plain `cast send` works.
